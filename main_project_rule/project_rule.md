# Ведение проектной документации

Храни всю проектную документацию в подкаталоге specification/.

Обязательные файлы:

- specification/__project.md — верхнеуровневое описание проекта, его архитектуры, интерфейсов, подсистем и текущего состояния.
- specification/work_plan.md — план работ, состояние каждого этапа, выполненные действия и результаты проверок.
- specification/work_experience.md — накопленный опыт работы над проектом: принятые решения, выявленные проблемы, ограничения, неудачные подходы и полезные наблюдения.

Если каталога или обязательных файлов нет, создай их до начала изменений.

## Порядок работы

Перед началом работы:

1. Полностью прочитай все файлы в каталоге specification/.
2. Определи текущее состояние проекта и последний завершённый шаг.
3. Не повторяй уже выполненные действия без явной необходимости.
4. Добавь или актуализируй текущий этап в work_plan.md.

Во время работы:

1. Поддерживай work_plan.md в актуальном состоянии.
2. После завершения каждого этапа укажи:
   - статус этапа;
   - выполненные действия;
   - полученный результат;
   - проведённые проверки и их результаты;
   - выявленные проблемы и ограничения;
   - следующий шаг.
3. Не отмечай этап завершённым, пока его результат не проверен либо явно не указано, почему проверка невозможна.
4. При изменении интерфейса, бизнес-логики, кода, поведения, геометрии, физических допущений, форматов данных или границ подсистем обновляй соответствующую спецификацию в том же цикле работы.
5. Документация должна описывать фактическое состояние проекта, а не только намерения.

После существенных изменений и перед завершением каждого рабочего цикла обнови документацию, зафиксировав:

- текущее состояние проекта и инфраструктуры;
- выполненные действия;
- результаты проверок;
- созданные резервные копии и точные пути отката, если они существуют;
- выявленные проблемы и ограничения;
- незавершённые действия;
- следующие необходимые шаги.

## Восстановление после сжатия контекста

После сжатия или восстановления контекста:

1. Полностью перечитай все файлы в specification/.
2. Используй документацию как источник истины о состоянии проекта.
3. Продолжай с первого незавершённого шага из work_plan.md.
4. Не повторяй завершённые действия, если документация и состояние проекта подтверждают их выполнение.
5. Если документация расходится с фактическим состоянием проекта, сначала зафиксируй расхождение и приведи документацию в соответствие с проверенными фактами.

Поскольку момент автоматического сжатия контекста может быть заранее неизвестен, сохраняй контрольную запись после каждого существенного этапа, а не рассчитывай только на запись непосредственно перед сжатием.
